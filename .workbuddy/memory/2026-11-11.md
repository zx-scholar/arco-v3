## 坑：mockjs 让 axios 上传报 "upload.addEventListener is not a function"

- 现象：上传页点/拖文件无任何网络请求，控制台报 `upload.addEventListener is not a function`
- 根因链：
  1. `src/main.ts` 无条件 `import './mock'`（生产也生效），mockjs 把 `window.XMLHttpRequest` 换成 MockXMLHttpRequest
  2. `mockjs/dist/mock.js:8352` → 该 mock 类的 `upload: {}` 是空对象
  3. `axios/lib/adapters/xhr.js:166` → 只要传了 `onUploadProgress` 就调 `request.upload.addEventListener(...)` → 抛错，`send()` 从未执行
- 修复：`src/api/upload.ts` 改为原生 XHR 实现（进度 / abort / 错误解析自己处理），构造器从 `window._XMLHttpRequest`（mockjs 在 `mock.js:8146` 备份的原生引用）取，fallback 到 `window.XMLHttpRequest`
- 附带：`src/utils/legacy-request.ts` 导出 `LEGACY_BASE_URL` 供上传拼接 URL
- 教训：这个项目里凡是要用 `xhr.upload`（上传进度）的地方都不能走 axios，除非绕开 mockjs 的 XHR

### 事故与修复：`husky --version` 污染 core.hooksPath

- 现象：提交报 `env: unknown option -- version/_/pre-commit`；`git config core.hooksPath` 的值变成 `--version/_`
- 根因：husky 9 的 bin **没有 `--version` 选项**。`bin.js` 里 `a=argv[2]` 直接传给 `index.js` 的 `(d='.husky') => git config core.hooksPath ${d}/_`，所以 `husky --version` 把 `--version` 当目录名写进 git 配置，还在项目根建了 `--version/_/`、`--help/_/` 两套 shim
- 修复：`git config --local core.hooksPath .husky/_`，再删掉 `./--help`、`./--version`
- 教训：查 husky 版本看 `node_modules/husky/package.json` 或 `pnpm list husky`，**永远不要**给 husky 传 `--xx` 参数；`pnpm exec husky`（无参数）才是"重新安装/修复"的正确命令
- 验证钩子的干净方式：`git hook run pre-commit`、`git hook run commit-msg -- <msgFile>`（git ≥2.36），不产生提交记录
